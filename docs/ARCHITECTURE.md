# How tred works

## Getting past VGA text mode's 256 characters

In VGA text mode each screen cell is two bytes: a character code and an
attribute (foreground colour in bits 0-3, background in bits 4-6, blink in
bit 7). One byte of character code means one font of 256 glyphs, and CP437
already fills those with box drawing, accented Western letters and symbols.
Vietnamese needs 134 extra letters (12 vowels with 6 tones in both cases,
plus đ/Đ), so they cannot fit next to CP437.

VGA has a way out that DOS programs rarely use: it can hold up to 8 fonts in
video memory, and the **character map select** register (sequencer register 3)
picks two of them, A and B. Attribute bit 3, normally the "bright" bit of the
foreground colour, decides which one a cell uses. With two fonts loaded, every
cell can show any of 512 glyphs. tred sets it up like this (`vgatxt.c`):

1. **Two fonts.** Font 0 holds the normal character set. Font 1 is a copy of
   it with the Vietnamese letters drawn over slots 0x80-0xFF and 0x01-0x06.
   INT 10h AX=1103h with BL=04h makes font 1 the one used when bit 3 is set.
2. **Bit 3 stops being a colour.** If it still made colours bright, every
   Vietnamese letter would also change colour. The attribute controller's
   colour plane enable register is set to 0x07 (INT 10h AX=1000h BL=12h), so
   bit 3 no longer reaches the palette and only picks the font. The price is
   8 foreground colours instead of 16.
3. **Two colours repainted.** edit.com's look needs bright white (hotkeys) and
   dark grey (shadows), which are among the colours lost in step 2. Palette
   entries 5 (magenta) and 6 (brown) are unused by the UI, so they are
   repainted to white and dark grey (`COLOR_WHITE`, `COLOR_DARKGRAY`).
4. **Codes above 0xFF.** Inside tred a character on screen is a 16-bit
   "cp437e" code: values up to 0xFF are font 0 glyphs, and 0x100 + slot is a
   font 1 glyph (`unicode_to_cp437e`, `VN_CODE`). When a cell is written,
   `MKCELL` turns that into a real cell: the low byte is the slot and
   attribute bit 3 is set for font 1 codes and cleared for everything else.
   UI code only ever passes colours 0-7.
5. **The mouse pointer keeps bit 3.** The mouse driver draws its text pointer
   by XOR-ing the cell under it. tred sets the XOR mask to 0x7700, which
   flips the colours but leaves bit 3 alone, so the pointer never shows a cell
   in the wrong font.

The font itself copies BKED, a Vietnamese DOS editor. It uses the 350-line
80x25 mode with 8x14 characters. The BIOS 8x14 font is moved down a row and
right a column, which leaves five rows above lowercase letters for diacritics;
line drawing characters stay where they are so boxes still join up. On exit
tred puts back the normal 400-line mode, which also reloads the BIOS font and
palette.

## Modules

All sources are in `src/`, C89 for 16-bit DOS, built with Open Watcom in the
huge memory model.

| Module | What it does |
| --- | --- |
| `main.c` | Parses the command line, sets up the screen, mouse and editor, and runs the main loop: handle every pending key or mouse event, then draw once. |
| `vgatxt.c` | VGA setup through the BIOS and the CRTC: 350-line mode, loading both fonts, plane and palette tricks above, the hardware cursor, and restoring the normal mode. |
| `vnfont.c`/`.h` | Generated by `tools/mkfont.py`: the sorted list of the 134 Vietnamese code points, their 8x14 glyphs, and BKED's redrawn ASCII glyphs. |
| `vncvt.c` | Unicode to cp437e: Vietnamese letters go to font 1 (binary search in the `vnfont.c` table), others map to their CP437 glyph or `■`. |
| `utf8.c` | Decodes and encodes UTF-8 and steps back one character. Invalid bytes decode as U+FFFD so they survive a round trip. |
| `surface.c` | The screen as two 80x25 cell buffers. `back` is what the UI draws, `front` mirrors video memory. Each row tracks the span that changed, and `scr_flush` writes only cells that differ, never reading video memory. Also saves and restores rectangles for menus and dialogs. |
| `draw.c` | Viewports: rectangles of the surface with clipped text, fills, UTF-8 strings and box frames. |
| `kbd.c` | Keyboard input through INT 16h, merged with mouse events, plus the `-k` key script used for automated tests (`{Enter}`, `{C-S}`, `{Click:x,y}`, `{Wheel:n}` and so on). |
| `mouse.c` | The DOS mouse driver (INT 33h): pointer setup, hiding it while video memory is written, and turning presses, releases, drags and wheel turns into events. |
| `textbuf.c` | The text as an array of lines of raw UTF-8 bytes. Loads and saves files, keeping CRLF or LF, a BOM and the final newline as they were, and does inserts, deletes, splits and joins. |
| `ime.c` | Telex and VNI input. It decomposes the word left of the cursor into letters with modifiers and tones, applies the key, puts the tone back on the right vowel and recomposes it. Pure C with host tests in `tests/t_ime.c`. |
| `editor.c` | The edit window: cursor movement, editing, word wrap, feeding keys to the IME, mouse clicks, and drawing the text view, frame, scrollbars and status bar. |
| `menu.c` | The menu bar, drop-down menus, message boxes, the input box and the File Open dialog. Each one saves what is under it and puts it back when it closes. |
| `port.h` | Lets the pure modules compile on a normal host compiler for the tests. |

### Drawing as little as possible

Video memory on old PCs is slow, so tred avoids touching it:

- The editor keeps a table of which piece of which line each of the 21 text
  rows shows (one line, or one wrapped piece of it). The table is rebuilt only
  after an edit or a scroll, and only rows whose content changed are decoded
  and redrawn.
- Everything else (frame, scrollbars, status bar) is redrawn into `back` every
  time. That costs a comparison per cell, and only cells that changed reach
  video memory.
- Scrolling by one row (cursor keys at the edge of the window, a wheel
  notch) shifts the row table and the screen buffer and lays out only the
  row that came into view.
- After an edit, rows above the edited line are kept, and laying out stops
  once the rows below line up with the old ones again.
- The cursor's row, its column for Up/Down and the status bar column come
  from the row table or are cached, instead of rescanning long lines.
- The main loop handles all keys typed ahead before drawing, so key repeat
  never queues redraws.

Typing a letter writes about 3 cells to video memory, and moving the cursor
1 or 2.

## Tools

| File | What it does |
| --- | --- |
| `tools/bked_glyphs.txt` | Glyphs traced pixel for pixel from BKED screenshots, as editable ASCII art. |
| `tools/mkfont.py` | Builds `src/vnfont.c`: traced glyphs as they are, and the Vietnamese letters BKED's screenshots don't show composed with BKED's mark placement. |
| `tools/dosbuild.sh` | Clean build of `src/tred.exe` inside DOSBox-X with the DOS-hosted Open Watcom tools. |
| `tools/dosrun.sh` | Runs tred in DOSBox-X with a key script, then dumps the screen with `vgadump`. |
| `tools/vgadump.c` | DOS program that saves text memory, the fonts in VGA plane 2 and a few registers. |
| `tools/dosbench.sh` | Times a few key scripts at a fixed DOSBox-X speed (300 cycles is roughly a 4.77 MHz XT). |
| `tools/vgarender.py` | Renders such a dump to a PNG, or prints it as text, to check what tred really drew. |
